Исходный аудит проверен по коду и по живому проду. **Четыре пункта из восьми
сняты**: они описывали состояние до слияния восьми веток 12.08 либо предлагали

Проверено прямой записью в живую базу тестовым владельцем: чтение `users` — ok,
`update avatar_url` — ok, `update full_name` — ok. Косметические правки можно
класть, продукт проходим.

## Правила для исполнителя

1. **Каждая задача — своя ветка от свежего `origin/main`, явно:**
   `git checkout -b fix/<имя> origin/main`.
   Сейчас в репозитории есть ветка `feat/landing-supply-first` — это отдельная
   работа по лендингу, **в неё не коммитить и от неё не ответвляться**.
2. **Не расширять задачу.** При правке подписи не трогать соседние константы,
   не чистить «заодно» мёртвый код, не менять цвета и шрифты.
3. **Отчёт без прогона не принимается.** В конце каждой задачи — вывод команд
   из раздела «Проверка», а не пересказ.
4. **Ничего из раздела «Снято» не чинить.** Там перечислено то, что уже
   сделано или сделано намеренно; «починка» вернёт удалённое.

## Задача 1. Баннер cookies по-английски на французском продукте

**Файл:** `src/components/CookieBanner.tsx`

**Подтверждено:** ни одного `useTranslation`, весь текст константами в коде —
`This site uses cookies`, `We use cookies to keep you logged in and, optionally,
to collect anonymous analytics`, `Accept all cookies`, `Manage cookies`.

Исходный аудит объяснял это тем, что баннер «отрисован вне контекста i18n» —
**это неверно**, баннер стоит внутри дерева `App`. Причина проще: переводов в
нём никогда не заводили.

**Что сделать:**
- завести ключи под `cookies.*` в `src/locales/fr.json`, `en.json`, `nl.json`;
- заменить константы на `t('cookies.…')` через `useTranslation()`;
- **French — исходный язык продукта.** Французский текст пишется первым,
  английский и нидерландский — переводы с него, а не наоборот.

**Чего не делать:** не менять логику согласия, ключ `rentit_cookie_consent` и
набор категорий (`necessary` / `functional` / `analytics`) — на них завязаны
снимки страниц и прогоны Playwright.

**Проверка:** `node scripts/check-i18n-keys.mjs` (все ключи во всех трёх
языках), затем баннер по кругу FR→EN→NL.

## Задача 2. Две кнопки «Partager» с одинаковой подписью

**Файл:** `src/pages/ItemDetail.tsx`

**Подтверждено построчно:**
- строка 240 — `{shared ? '✓ Copié !' : '↑ Partager'}` — копирует ссылку
  (`navigator.share` с откатом в буфер, строки 125–126);
- строка 260 — `Partager` — ведёт в WhatsApp через `wa.me/?text=…` (строка 243).

Различить их на экране нельзя.

**Что сделать:** развести подписи по действию. Первая — «Copier le lien»,
вторая — «Partager sur WhatsApp». Обе подписи через словарь, во всех трёх языках.

**Чего не делать — три запрета, каждый стоил бы отката:**
- **не переписывать `wa.me/?text=` и не удалять кнопку.** Ссылка без номера
  никого не раскрывает; ею делятся объявлением, а не переписываются с
  контрагентом;
- **не трогать `scripts/check-claims.mjs`** (см. «Снято», п. Б);
- **не назначать кнопке новый цвет.** Сейчас на ней `#25D366` мимо палитры —
  это верно подмечено, но фирменные цвета продукта сейчас пересматриваются
  целиком. Цвет придёт вместе с новой палитрой; в этой задаче только подписи.

**Проверка:** `node scripts/check-claims.mjs` (обязан остаться чистым — слово
«WhatsApp» в подписи попадёт под запрет, поэтому подпись хранить в словаре и
убедиться, что страж на неё не ругается; если ругается — задача решена неверно,
доложить, а не глушить правило).

выбор «Business» вести некуда, пока платной модели нет.

**Проверка:** `npx tsc --noEmit`, `npm run build`, `node scripts/check-claims.mjs`
(в `parked/` страж не смотрит — это и есть причина, по которой файл едет туда,
а не остаётся в `src/`).

## Задача 4. Сообщение об ошибке жёстко по-французски

```js
onError: (error) => {
  toast.error(error.message || 'Une erreur est survenue');

```

**Что сделать:** вынести запасную строку в словарь (`errors.generic`) и брать

а техническое сообщение оставить в `console.error`.

**Проверка:** `node scripts/check-i18n-keys.mjs`, `npx tsc --noEmit`.

## Задача 5. Ложное обещание на проде, мимо стража

**Файл:** `index.html` (корень проекта, не `src/`)

```html
<meta property="og:description"
      content="P2P location d'outils entre voisins en Belgique. Protection incluse." />
```

**Это живёт на проде прямо сейчас** — проверено `curl` по
`https://rentit-plum.vercel.app/`. «Protection incluse» — обещание страховки,
вычищенное из интерфейса 11–12.08. Именно этот текст показывается в превью
ссылки, то есть первым читает тот, кому ссылку прислали в мессенджер.

Страж его не видит по устройству: `SCAN_DIRS = ['src']` в
`scripts/check-claims.mjs`, а `index.html` лежит в корне.

**Что сделать — двумя частями:**

1. **Текст.** Заменить `og:description` на честный. Годится:
   `Louez des outils entre voisins en Brabant Wallon. Sans commission, règlement en espèces.`
   Заодно проверить `og:title`, `description` и JSON-LD в том же файле на
   такие же остатки.
2. **Класс.** Расширить `SCAN_DIRS` в `scripts/check-claims.mjs`, чтобы страж
   читал `index.html` и файлы в `public/`. Правило перестало быть слепым не
   потому, что кто-то запомнил про этот тег, а потому, что тег теперь
   сканируется.

**Проверка:** `node scripts/check-claims.mjs` — после расширения он обязан
поймать старую формулировку, если её вернуть. Проверить это намеренно:
временно вписать «Protection incluse», убедиться, что сборка падает, вернуть
честный текст.

**Отдельно, НЕ в эту задачу** (нужно решение Рамзана): `og:image` указывает на
`.svg`, а Facebook, LinkedIn и WhatsApp SVG в превью не отображают — картинки
в превью нет вовсе. И `hreflang` ведёт на `https://rentit.be`, тогда как прод
живёт на `rentit-plum.vercel.app`; чей это домен — не проверено.

## Снято — не чинить

**А. «Два i18n» (п. 1 исходного аудита).** Закрыто 12.08, PR #8 (`235fbef`).
Проверено: каталога `src/i18n/` не существует, импортов старой системы в коде
ноль, переключатель ходит FR→EN→NL по кругу. Попытка «мигрировать на
react-i18next» принесёт вторую систему словарей — ровно ту, которую убрали.

**Б. «Страж слеп к `wa.me`» (п. 5).** Неверно. Правило стоит в
`scripts/check-claims.mjs:128`:

```js
{ word: /wa\.me\/[^?\s'"`]/i, why: 'Ссылка вида wa.me/<номер> раскрывает чужой телефон.' }
```

Оно ловит `wa.me/<номер>` — то, что раскрывает чужой телефон, — и намеренно
пропускает `wa.me/?text=`, где номера нет. Предложенный в аудите шаблон
`/wa\.me\/\?text=/i` запретил бы как раз безопасный случай и сломал бы рабочую
кнопку.

**В. «Подвал противоречит модели» (п. 2).** Не дефект. Ссылка «Pour les magasins
de location» ведёт на `/rental-shops` — страницу, сделанную намеренно 12.08,
PR #6 (`c3328f0`), взамен мёртвого `<span>`, висевшего полгода. Аудит предлагает
её удалить: это откат решения, а не багфикс. Развороты решений идут через ADR.

**Г. «Мобильная катастрофа: семь фильтров на весь экран» (п. 7).** Опровергнуто
снимком живого прода при 390px: на витрине три органа — поиск, «À proximité» и
свёрнутые «Filtres ▾». Пустое состояние видно без прокрутки и не тупиковое:
«Aucun outil dans cette zone» → «Soyez le premier à déposer une annonce ici» →
кнопка «Déposer votre premier outil →» и «Élargir à 50 km». Фильтры свёрнуты
12.08.

*Отдельно: на лендинге при 390px обрезка есть* — панель «Revenus par location»
режет текст до «Gratui» и «Annonc» внутри блока с `overflow: hidden`
(`scrollWidth` при этом равен `innerWidth`, прокрутки документа нет). Это
**задача лендинга**, она ведётся в своей ветке — сюда не брать.
